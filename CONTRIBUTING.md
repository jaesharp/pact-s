# Contributing to PACT-System

We welcome contributions to the PACT-System framework! Whether you're interested in refining the core principles, developing new protocols, adding tool integrations, or improving documentation, your input is valuable.

## How to Contribute

We are in the early stages of defining formal contribution processes. For now, please consider the following ways to contribute:

1.  **Discussions & Feedback**: Engage in discussions (e.g., if this project moves to a platform with an issue tracker or discussion forum) regarding the PACT-System concepts, plans, and documentation. Your feedback on clarity, completeness, and applicability is highly appreciated.
2.  **Identifying Issues**: If you find errors, inconsistencies, or areas for improvement in the documentation or conceptual framework, please note them for discussion.
3.  **Proposing Enhancements**: Suggestions for new features, protocols, tool symbolic references, or architectural refinements are welcome. These can be discussed and potentially incorporated into the relevant planning documents (see [`.plans/README.md`](./docs/plans/README.md)).

## Getting Started (Conceptual - For Future Code Contributions)

While the PACT-System is currently primarily a conceptual framework and a set of specification documents, future development may involve reference implementations or tooling. If and when that happens, this section will be updated with details on:

*   Setting up a development environment.
*   Key technologies used (e.g., Haskell, Dhall, OWL/XML tooling).
*   Building and testing any provided code.

## Development Workflow & Code Contributions (Future)

When code contributions become applicable, we will adhere to the following (referencing the detailed plan in [.plans/vcs_strategy.md](./docs/plans/vcs_strategy.md)):

*   **Branching Strategy**: A GitFlow-like model (main, develop, feature branches).
*   **Commit Messages**: Adherence to Conventional Commits specification.
*   **Pull Requests (PRs)**:
    *   PRs should be made against the `develop` branch.
    *   Include a clear description of changes and link to any relevant issues or planning documents.
    *   Ensure any new code includes appropriate tests (see [.plans/testing_strategy.md](./docs/plans/testing_and_verification/README.md)).
    *   Update relevant documentation along with code changes.
    *   PRs will require review and approval.
*   **Code Style & Linting**: (To be defined - likely Prettier, ESLint for TS, or language-specific formatters/linters for Haskell/Dhall if used).

## Documentation Contributions

Contributions to documentation are highly encouraged. This includes:

*   Improving clarity and accuracy of existing documents.
*   Adding examples or use cases.
*   Identifying and filling gaps in documentation (see [.plans/documentation_strategy.md](./docs/plans/documentation/README.md)` and `[.plans/documentation_alignment_plan.md](./docs/plans/archived_or_reference_materials/documentation_alignment_plan.md)).
*   Proposing new documentation sections or guides.
*   All documentation should adhere to the PACT-System nomenclature and principles.

## Reporting Bugs or Suggesting Enhancements

(This section will be updated if/when a formal issue tracker is established for the project.)

*   **For now**: Discuss potential bugs or enhancements conceptually. If this project moves to a platform like GitHub, use the issue tracker there.
*   **Provide Context**: When reporting a bug or suggesting an enhancement, please provide as much context as possible, including:
    *   The specific document or concept you are referring to.
    *   The nature of the bug or the proposed enhancement.
    *   Your rationale and any supporting examples.

## Code of Conduct

All contributors are expected to adhere to a Code of Conduct that promotes a welcoming and inclusive environment. (A formal Code of Conduct, such as the Contributor Covenant, will be adopted and linked here if the project becomes more public or collaborative.)

For now, please ensure all interactions are respectful and constructive.

## Questions?

If you have questions about contributing or about the PACT-System, please raise them for discussion.
